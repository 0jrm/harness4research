## How work is done here

- **Pull requests.** Every change goes on a branch from `main` and gets a pull request to `main`; never stack pull requests. Write the review brief at `$(git rev-parse --git-common-dir)/guard/briefs/<branch with / as ->.md`, with the owner's words verbatim. Run `guard review <pr>`, fix and rerun it until it approves, then `guard merge <pr>` once CI passes. Never run `gh pr merge`.
- **Workflow files.** The agent token cannot push `.github/workflows/`. Prepare the change, and let the owner push it.
- **The measured path.** Anything that changes the harness's guard scripts, the fence or preflight must keep `eval/audit/run.py` green for the rows it should hold: run it before and after, and update `docs/enforcement-audit.md`.
- **Records.** Keep the local ledgers `.audit/present-eval-handoff.tsv` and `.audit/decisions-eval-pilot.tsv` (append-only), and the needs-you queue for anything a person must decide. Only the owner closes queue items.
- **Commands for the owner.** One fenced block with short `#` comments, pastable whole, followed by expected and worrisome output. Never put a quoted multi-word argument in a command.
- **skynet.** Never use `pkill -f` or `pgrep -f` over ssh: the pattern matches the ssh session's own command line and kills it. Find process IDs with `ps -o pid=,args= | awk '/pattern/ && !/awk/'`, then kill by ID. Cap every wait loop. Git and builds on skynet's NFS home take minutes; the evaluation lives on `/conda/jmiranda/h4r`. Our vLLM server is stopped (2026-10-14).

- **The fence** freezes a question card even when it is added and edited in one push, and it protects `AGENTS.md` and `CLAUDE.md` like `guard/`.
