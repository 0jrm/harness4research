# Release v6.2

Guard schema 6, as in [v6.1](v6.1.md). No rule, key, check name or exit code of a guarded project changes. The scripts under `guard/` are the same as in v6.1, so a project's update changes only `guard/VERSION`.

## Changes since v6.1

- **`guard pr open`** (W0.5). It writes the branch's brief from a file holding the user's words verbatim, pushes the branch, and opens the pull request titled `[<item>] <title>`. It refuses a body that repeats a line of the request, so the user's words stay on the machine. A rerun on a branch that already has an open pull request prints its URL and changes nothing. The review-and-merge skill now opens pull requests with it.
- **Shorter skills and agent notes** (#111). Each skill's `SKILL.md` keeps its rules, lifecycle and formats in under 900 words, and the rest moves word for word to the skill's `references/`, linked with when to open it. The science rules are unchanged. `templates/AGENTS.md` is 250 words, with every rule kept, and the reviewer prompt is 595 words. `tests/budget.sh` keeps them there.
- **The test suites check their prerequisites first** (#109). `tests/run.sh` needs jq, PyYAML, the full history and the release tags; the evaluation's self-test and audit need bubblewrap with user namespaces. A missing one prints one line with the fix and exits 64.
- **The enforcement audit gates pull requests** (#107, #108). `eval/audit/run.py --gate eval/audit/baseline.json` fails when a row the baseline holds no longer holds. This affects the harness's own development, not projects.
- **The evaluation's broker, increment 1** (#110). In the evaluation's sandbox, jobs go through a broker that renders `sbatch` itself; the audit holds 45 of 50 rows. Evaluation only: a guarded project does not use the broker yet.

## Update a project from v6.1

```bash
# update the harness clone, then propose the guard update on a branch
git -C ~/harness4research fetch --tags && git -C ~/harness4research checkout v6.2
guard init <repo> --update
```

The update changes `guard/VERSION` only. A person merges it, because it changes `guard/`. The skills follow the harness clone, so the checkout updates them. `guard init --update` never edits a project's AGENTS.md: compare it with `git -C ~/harness4research diff v6.1 v6.2 -- templates/AGENTS.md`, which rewords lines and changes no rule.

## Roll back

Revert the update pull request, and check out `v6.1` in the harness clone.
