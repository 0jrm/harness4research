# Release v6.1

Guard schema 6, as in [v6.0](v6.0.md). This release changes wording and tests only: no rule, key, check name or exit code changes.

## Changes since v6.0

- **A new run's domain checks ride the pull request with its question card** (#104). The safe-autonomous-hpc-science skill asks for checks written from the card's metric and kill criteria before any result exists, committed with the card, so one merge by a person approves both. A check added later still goes in a pull request of its own. The AGENTS.md template names this as the one exception to "watched paths belong to the human". Preflight's and launch's refusal, ripples' `domain-checks` remedy and ripples' `watched-paths` remedy say the same; the last one no longer tells an agent to revert checks committed on a card's branch, only to submit nothing until a person merges them.
- **The upgrade tests handle the v6.0 tag** (#103).

## Update a project from v6.0

```bash
# update the harness clone, then propose the guard update on a branch
git -C ~/harness4research fetch --tags && git -C ~/harness4research checkout v6.1
guard init <repo> --update
```

The update changes `guard/bin/preflight.sh`, `ripples.sh` and `launch.sh` (messages only) and `guard/VERSION`. A person merges it, because it changes `guard/`. The skills follow the harness clone, so the checkout updates them. `guard init --update` never edits a project's AGENTS.md; it prints the command to compare it with the template.

## Roll back

Revert the update pull request, and check out `v6.0` in the harness clone.
