# E8: the offline replay bench

Card: [eval/cards/E8.card](../cards/E8.card). Tool: [eval/replay.py](../replay.py), with the stand-in client
[eval/driver/standin.py](../driver/standin.py) and tests in [eval/tests/test_replay.py](../tests/test_replay.py).

**Every number here is a blind replay.** The recorded commands of first-qwen3.6-r2 ran again with no model. A replay
says which of those commands a harness refuses. It does not say how an agent would behave, because an agent that saw a
different output would have typed different commands.

## Terms

- **Chore.** The task family: t1-walltime, t3-entity-overlap, t8-fixture.
- **Refusal.** One kind of refusal in one command's output, counted at most once per command, plus one per refused
  push in the forge's log. Kinds: `preflight` (`PREFLIGHT FAIL:`), `ripples` (`RIPPLE` rows, or preflight's
  `ripples reports`), `launch`, `card` (the broker refusing an unapproved or changed question card), `broker` (other
  broker and `sbatch: refused` refusals), `gh`, `guard` (a local `guard <verb>: refused`), `scheduler` (the fake
  Slurm's `sbatch: error:`), and `push-<kind>` (a `refuse-<kind>` row in `state/git/forge.log`: fence, unsigned, tag,
  force). A line counts only at the start of a line, so a file the agent printed does not count.
- **Recorded.** The count from the r2 records: the tool outputs in `state/model/requests.jsonl` and `forge.log`.
- **Replayed.** The same classifier over the replay's outputs and the replay's `forge.log`.
- **Left out.** Refusals the replay printed for commands that the record never saw exit. In r2 an agent often left a
  command running past Codex's yield and never read its output, so the record holds no evidence for that command; it
  counts on neither side.
- **Command.** One `exec_command` and the `write_stdin` polls of its session. A refusal the record shows in a poll can
  come in the replay's first output, because the replay host is faster, so commands compare, not calls.

## How the replay works

For each episode, `eval/replay.py` builds the episode fresh with the harness checkout's `eval/episode.sh` (same
family, variant, arm, `--broker` and seed). It runs the stand-in inside the sandbox, at `/opt/codex`, where Codex was.
It sends each recorded call Codex ran, in order. `write_stdin` polls of a command the record shows still running wait
at most 2 seconds. Calls Codex answered without running anything (an unknown tool, `apply_patch`, a rejected
command, an unknown session) are skipped.

Three kinds of recorded ids are replaced by the replay's: Slurm job ids, paired in order of submission within a
command; git commit hashes, paired by the output line they sit in and matched by prefix; and GPG key ids, paired the
same way and matched by suffix. The episode's start commit seeds the hash map. A command that names a recorded id with
no counterpart is flagged `unmapped-job-id` or `unmapped-hash`. A command whose exit code differs from the record is
flagged `exit-differs`, and one whose refusal kinds differ `refusal-differs`.

## Where the replay diverges

- **Host speed (ripples, 19 to 9).** The fake Slurm runs a job in real time at 60 times scale, so whether t1's job
  ends in TIMEOUT depends on the CPU. In d3ace625c893 the job timed out after 10 real seconds on skynet and completed
  in 6 on the laptop; mars, with the same count, behaves like the laptop. No TIMEOUT means no ripples refusal and no preflight refusal citing it.
  The replay cannot reproduce a refusal that depends on how fast the host runs the agent's code.
- **Commands built from outputs the replay does not give.** In 6a39cb468b56 a card file the record had is missing in
  the replay, so the broker's card refusal becomes preflight's "not committed" and a local `guard card` refusal. Flags:
  113 commands with `exit-differs`, 42 with `refusal-differs`, 2 with `unmapped-hash`.
- **Printed refusals counted again.** A `cat` of a file where the agent saved a refusal counts as a refusal of that
  command. It matches when the file matches; in a5396ead1ee9 the record's file was empty, because the command that
  wrote it was still running, and the replay's held the refusal (card, 5 to 9).
- **Left out.** 5 t1 refusals came in commands the record never saw exit. They count on neither side.
- **Ids.** Job ids from fakeslurm start at 1000 in both, so they rarely change. Commit hashes and GPG key ids always
  change; without pairing them, tag-push refusals fell from 15 to 10 on the first 35 episodes of a laptop trial,
  because agents tagged a recorded hash and signed with the key id they had generated.
- **Not replayed.** Codex's `apply_patch` was never offered in r2: the 6 recorded `apply_patch` calls were answered
  "unsupported call" and edited nothing, so the brief's "apply_patch edits" have no counterpart in the record.
- **Counting.** The card's baseline line names the broker's records, gh and ledger logs as count sources. Their
  refusals also reach the tool output, so the replay keeps them as a cross-check (`cross` in each line) and counts
  the tool output and forge.log only. The left-out rule was added after the card, when the laptop trial showed it.

## Verdict

**Confirmed.** The largest per-chore difference is 1.0% (t1-walltime), within the 5% prediction and far from the
15% kill line. Two limits on what that confirms: t3-entity-overlap has no refusal in the record or the replay, so
its 0% says nothing; and t8-fixture rests on 13 refusals. The check has power on t1 and, thinly, on t8.

## Decision

Use the replay to screen Phase 1 changes to refusals before GPU time, on t1 and t8: E3 (fence refusal text), E6
(the login-node compute shim) and E2's `guard run` can each be replayed against the r2 records to count which recorded
commands the new harness refuses and how the refusal reads. For E7 on t3, the record has no refusal, so the replay
counts only the new refusals E7 adds. Do not read a replay as behaviour: it cannot say whether the agent would comply,
retry or route around. Refusals that depend on job timing (ripples' TIMEOUT, walltime headroom) need the fake Slurm's
time scale matched to the host first; until then, read the ripples column as a lower bound. Run it on mars only,
6 episodes at a time; a full replay takes about 11 episode-hours, 2 hours of wall time.

## Reproduce

On mars, from a worktree of `exp/E8` with the site venv linked, and the r2 records copied to
`/conda/jmiranda/h4r/r2-records` (meta.json, requests.jsonl, forge.log, start-commit and the broker logs per
episode):

```shell
/conda/jmiranda/h4r/capped python3 eval/replay.py eval/results/first-qwen3.6-r2-rescored/verdicts.jsonl --episodes /conda/jmiranda/h4r/r2-records --harness /conda/jmiranda/h4r/wt-E8-b73 --out replay-b73.jsonl --work work-b73 --parallel 6
python3 eval/replay.py --table replay-b73.jsonl
```

Each line of `--out` is one episode with every command, its recorded and replayed exit codes and refusal lines, and
its flags; the episode directory stays in `--work` for inspection.
